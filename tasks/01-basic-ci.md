# Задание 01. Базовый CI — GitHub Actions

**Цель:** написать первый workflow: тесты запускаются автоматически на каждый
push и pull request.

## Шаги

1. Создайте файл `.github/workflows/ci.yml` (папки `.github/workflows/` нет —
   создайте). Структура workflow:
   - `name`: любое, например `CI`
   - `on`: push в ветку main + pull_request
   - один job `test` на `ubuntu-latest` с шагами:
     1. `actions/checkout@v4`
     2. `actions/setup-python@v5` с `python-version: "3.12"`
     3. установка зависимостей: `pip install -r app/requirements.txt`
     4. запуск тестов: `pytest app/tests -v`

   Документация: https://docs.github.com/en/actions/writing-workflows/quickstart

2. Закоммитьте и запушьте:
   ```bash
   git add .github/workflows/ci.yml
   git commit -m "Add CI workflow"
   git push
   ```

3. Откройте на GitHub вкладку **Actions** (верхнее меню репозитория).
   Кликните на запуск → на job `test` → разверните шаги и посмотрите лог.

4. **Обязательная часть — сломайте тест.** Измените в
   `app/tests/test_calculator.py` ожидание `add(2, 3)` на `== 6`, запушьте.
   Дождитесь красного прогона, откройте лог, найдите строку с FAILED.
   Затем верните как было (`git revert HEAD` или правкой) и запушьте —
   прогон должен снова стать зелёным.

## Критерий выполнения

- Во вкладке Actions есть минимум три запуска workflow: зелёный → красный → зелёный
- На странице последнего коммита стоит зелёная галочка
- Вы можете показать в логе строку с упавшим тестом

## Вопросы для самопроверки

1. Чем `uses:` отличается от `run:`?
   - uses использует готовые кубики (steps), а run выполняет непосредственно ваш код
2. Кто предоставляет виртуальную машину, где выполняется job? Какая на ней ОС?
   - виртуалку предоставляет гитхаб. ОС мы задали сами — ubuntu-latest
3. Что произойдёт, если открыть Pull Request в свой же репозиторий?
   - запустится наш только что созданный ci action
